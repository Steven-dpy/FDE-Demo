1问题 The Problem

家居电商的转化漏斗有一个固定漏点：需求模糊的访客。

他们进站时没有一个明确的目标。搜索框要求他们先知道关键词，分类导航要求他们先知道品类—— 而他们真正想说的是：

真实用户语言
「我想弄个能窝着看书的地方」
「小户型，东西多，怎么收」

这类输入落在现有系统里会变成两条死路：搜索框返回零结果，分类导航把责任推回给用户。 结果就是——访客流失，而店主甚至不知道他想要什么。

为什么这个问题值得用 AI 解决

子问题规则能解吗AI 能解吗
商品按价格/品类筛选✅ 完全能❌ 不需要
商品按关键词匹配✅ 完全能❌ 不需要
把「窝着看书」理解成一个场景❌ 做不到✅ 这是核心
判断缺哪些信息、该追问什么❌ 做不到✅ 这是核心
给出「为什么推荐这个」的理由❌ 做不到✅ 这是核心
设计原则
如果一个子问题规则能解，就不该用 AI。搜索、筛选、排序全部用规则实现—— AI 只用在它真正不可替代的地方：理解模糊意图、组织成套方案、生成推荐理由。

2方案 The Solution

Nook 是一个可嵌入客户网站的 AI 导购组件。它做三件事：

  1. 听懂场景——「能窝着看书的地方」→ 识别为「阅读角」，而不是去找名字里带"看书"的商品
  2. 成套给方案——阅读角需要椅子 + 灯 + 台面。给的是一个组合和总价，不是一个孤立商品
  3. 说清为什么——每件都带推荐理由；没有结果就直说，并说明放宽了什么条件

系统架构

实线为请求路径。注意左侧回环：检索无结果时会回到编排层放宽条件，而不是返回空列表。

一个容易忽略的细节
预算回显用的是用户自己说的那个数（¥10,000），而不是换算回人民币的近似值（¥9,994）。 第一版就是回显近似值，看起来像系统算错了。

3.4　一行代码，嵌进任何网站

为什么这是交付的前提，而不是锦上添花
你不能要求客户为了装你的组件去改自己的样式表。 用 iframe 能做到隔离，但会带来跨域、滚动、尺寸、SEO 一堆问题；Shadow DOM 是更干净的做法。

4关键设计决策 Key Decisions

01场景组包，而不是单品检索

「没有明确目标」的用户要的不是一件商品。系统识别场景后，按品类均价占比分配预算， 每个品类选最优，给出组合、总价和搭配理由。

取舍：如果只做单品检索，这个项目就退化成"带自然语言的搜索框"， 而搜索框恰恰是问题的起点，不是解法。

02最多连问两个问题，然后必须先给一版推荐

导购不是问卷。用户说了一句话，你连问三句，他就走了。 所以第二轮一定是「先给结果 + 附带一个细化问题」。

取舍：这牺牲了一部分推荐精度（信息不全），换来的是不把用户问跑。 测试里专门有一条断言：第二轮必须返回商品，不能继续追问。

03没有结果就说没有，放宽了什么要说清

检索按 尺寸上限 → 材质 → 风格 → 标签 逐级放宽软条件， 但回复必须写明「为了有结果，我放宽了『材质』」。

取舍：绝不硬凑一个不相关的商品充数。 对导购产品来说，一次胡说比一次"没找到"伤害大得多。

04检索层不依赖 LLM

槽位抽取、场景识别、检索、排序全部用规则 + IDF 词法实现，做到可复现、零成本、离线可跑。 LLM 是增强（更自然的表述），不是前提。

取舍：这放弃了 LLM 在长尾表达上的泛化能力， 换来的是一个永远不会因为 API 挂掉而整体失效的基线——而且它让评测变得可复现。

05价格与库存只从数据库读，不经过模型

商品库的基准货币只有一套 USD，中文界面按汇率折算显示； 所有价格、库存、SKU 都直接从数据层取。

取舍：不是用 prompt 约束模型"不要编造"，而是结构上让它编不出来。 电商场景里一个不存在的商品或价格，是直接的法律和客诉风险。

6复盘与下一步 Retrospective

做对了什么

  • 先定"AI 该用在哪"，再动手。把子问题逐个判断"规则能解吗 / AI 能解吗"， 排除了搜索和筛选这两块完全不需要 AI 的部分。
  • 先建可工作的基线，再加增强。检索层不依赖 LLM，所以系统永远有一个能跑的版本， 评测也可复现。
  • 把护栏放在数据层，而不是 prompt 里。价格和库存结构上就不可能被编造。

已知不足

  • 跨语言排序仍有微差。中文和英文问同一件事，返回的是同一批 SKU， 但近似同分时前两名顺序可能互换。词法检索的固有问题，加确定性 tiebreaker 缓解但没根治。
  • 场景库是人工维护的。目前 5 个场景（阅读角 / 居家办公 / 有孩子的客厅 / 小户型 / 阳台）， 靠关键词触发。长尾场景覆盖不到，下一步考虑用 LLM 做场景抽取。
  • 预算分配是均价比的线性分配。不会主动"把预算用满"去推荐更好的商品， 保守但不总是最优。
  • 商品图是公共图库随机图，不是真实家具照片，演示观感受影响。

下一步

  1. 评测集与指标报告：场景识别准确率、推荐采纳率、幻觉率（应恒为 0）、平均轮次、单次对话成本
  2. 可选 LLM 增强层：接 OpenAI 兼容端点，无 key 自动降级； 做成对照实验——规则基线 vs LLM 增强，用数据说明 LLM 到底带来多少提升
  3. 店主配置台：品牌语气、开场白、推荐策略可视化调整
  4. Docker 化 + 接入文档

English Summary

Nook — an embeddable AI shopping concierge for independent furniture retailers.

Shoppers rarely arrive knowing what they want. They don't type "Scandinavian solid-oak three-seat sofa" — they say "I want a corner where I can curl up and read." A search box can't take that input.

What it does

  • Understands scenarios, not keywords — "curl up and read" is recognised as a reading corner, not a product-name lookup.
  • Recommends a set, not an item — chair + floor lamp + side table, with a budget split across categories and a total price.
  • Explains the reasoning — every recommendation carries its "why". When nothing fits, it says so and states exactly which constraints it relaxed.

Delivery: one <script> tag. Shadow DOM keeps the widget's styles isolated from the host site in both directions — the client never has to touch their stylesheet.

Engineering: 240 SKUs, bilingual catalogue, zero third-party dependencies, 33 automated tests. Prices and stock are read straight from the data layer — the model structurally cannot invent a product or a price.

Fern & Oak 及其商品、价格、库存均为虚构数据，用于演示。 商品图片来自公共图库占位，加载失败时自动回退到本地生成的占位图。
