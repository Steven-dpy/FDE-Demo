# Nook

**可嵌入独立站的 AI 导购引擎** —— 帮「没有明确目标的买家」找到东西。

> 虚拟客户：**Fern & Oak**（家居独立站，双语，240 个 SKU）
> 交付形态：客户在自己网站加**一行 `<script>`**，右下角出现 AI 导购。

---

## 这个项目在做什么

买家居的人常常说不清自己要什么。他们不会在搜索框里输入「北欧风格 实木 三人沙发」，
他们会说：**「我想弄个能窝着看书的地方。」**

传统电商搜索框对这个输入无能为力——它不是关键词，它是一个**场景**。

Nook 做三件事：

1. **听懂场景** —— "能窝着看书的地方" → 识别为「阅读角」，而不是去找名字里带"看书"的商品
2. **成套给方案** —— 阅读角需要椅子 + 灯 + 台面。给的是一个**组合**，不是三个孤立商品，且按预算分配
3. **说清为什么** —— 每件都带推荐理由；没有结果就直说，并说明放宽了什么条件

## 架构

```
用户一句话
   │
   ▼
[槽位抽取]  extract()          规则实现，不依赖 LLM
   │  品类 / 房间 / 风格 / 材质 / 标签 / 预算 / 尺寸上限
   │  ← 中文数字解析：「预算一万」→ 10000；拉丁词按 \b 边界（read 不命中 already）
   ▼
[币种处理]  money.to_usd()     中文界面 → 人民币 ÷ 7.2 = 基准 USD
   │
   ▼
[场景识别]  detect_look()
   │
   ├── 命中场景 ──► [场景组包] 按品类均价占比分配预算 → 每类选最优
   │
   └── 未命中 ────► [检索]  结构化硬过滤 + IDF 加权词法打分
                        │        无结果 → 逐级放宽软条件，并如实上报
                        ▼
                   [推荐 + 理由 + 双币价格]
                        │
                        ▼
              POST /api/chat  →  widget 渲染卡片
                        │
                   nook:add-to-cart 事件 →  宿主页面购物车
```

## 五个关键设计决策

**1. 场景组包，而不是单品检索**
"没有明确目标"的用户要的不是一件商品。给组合、给总价、给搭配理由，这才叫导购。

**2. 最多连问两个问题，然后必须先给一版推荐**
导购不是问卷。用户说了一句话，你连问三句，他就走了。所以第二轮一定是「先给结果 + 附带一个细化问题」。

**3. 没有结果就说没有，放宽了什么要说清**
检索按 `尺寸上限 → 材质 → 风格 → 标签` 逐级放宽软条件，但回复必须写明「为了有结果，我放宽了『材质』」。**绝不硬凑。**

**4. 检索层不依赖 LLM**
规则 + IDF 词法做到了可复现、零成本、离线可跑。LLM 是**增强**（更自然的表述），不是**前提**。这个顺序让系统永远有个能工作的基线。

**5. 嵌入用 Shadow DOM，不是 iframe**
客户不需要改自己的样式表，Nook 也不会污染客户的页面——在一个深色衬线站点上，
widget 依然是自己那套配色和圆角。**这是能不能交付的前提，不是锦上添花。**

## 货币处理

商品库的**基准货币只有一套：USD**，不重复维护两套价格。

- 英文界面：只显示 USD
- 中文界面：双币显示 `US$1,299 ≈ ¥9,353`

关键细节：**中文用户输入的预算按人民币理解**——因为他在界面上看到的就是 ¥。
所以「预算一万」= ¥10,000 ÷ 7.2 = US$1,389 用于过滤。

另一个细节：预算回显用**用户自己说的那个数**（¥10,000），而不是换算回去的近似值（¥9,994）。
否则用户会以为系统算错了。

汇率通过环境变量可调：`NOOK_USD_CNY=7.20 python server.py`

## 真实迭代记录

开发中修掉的实际问题（保留下来，因为它们比"一次写对"更真实）：

| 问题 | 现象 | 修法 |
|---|---|---|
| SKU 撞车 | `dining_table` / `dining_chair` 都截成 `FO-DIN-` | 改显式编码表，不靠 `cat[:3]` |
| 名称耗尽 | 48 个地名不够 240 个产品，出现重名 | 用「地名 + 自然词」组合补足 |
| KeyError ×2 | `accents` 池混了颜色词；`hallway` 房间缺失 | 查找回退到 COLOR 表；补全 ROOM 表 |
| **中文数字没解析** | 「预算两千五」被忽略，重配了却没变化 | 实现 `cn2num()`，处理「两千五 = 2500」口语省读 |
| **正则贪婪吞字符** | 「预算三万」解析成 `万` → 0 | `\D{0,4}` 改惰性 `\D{0,4}?` |
| 参数传错 | 英文澄清分支把问题字符串当商品列表，直接崩 | 修 `_reply()` 调用签名 |
| 词边界误判 | `read` 命中 `already` / `spread` | 拉丁关键词改 `\b` 匹配 |
| **汇率精度漂移** | 预算 ¥10,000 回显成 ¥9,994，像算错 | 回显用户原话，不用换算近似值 |
| 排序不确定 | 近似同分时每次顺序可能不同 | 加 SKU 兜底排序，保证可复现 |
